# Forensic audit — build 2026-05-29 v16 (post-v15)

**Audit window:** 2026-05-30 (Asia/Bangkok), post-v15 wave.
**Baseline state:** branch `docs/agent-wake-up`, HEAD `e783013`,
working tree clean. PDF sha256
`6d2e29ed32cc92b4aea32a0c639f7f16c646d94e1aa4adba97787869ec79293d`

This audit is the input to the **v16 critic-proof pass**. It finds

## P0 — link rot and false references (critical)

### P0.1 — `docs/audits/build-2026-05-29-v13.md` was never committed but is linked from README / CLAUDE / AGENTS

The v15 P0 commit (`12f59c4`) added explicit Markdown links to
three audit files: v13, v14, and v15. The v14 and v15 files exist;
the v13 file **does not and never did**:

```
$ git log --all --oneline --diff-filter=A -- 'docs/audits/build-2026-05-29-v13.md'
(empty)
$ ls docs/audits/ | grep -c build-2026-05-29-v13
0
```

The v13 work was committed (`0804d7c`, `1295db5`, `30cbee1`) but
none of those commits added a v13 audit document — they edited
rule files directly. The v14 audit retroactively refers to a "v13
forensic audit" that exists only as the commit log, not as a
document. v15 then linked to the nonexistent file in three
entry-point docs.

**Impact:** any reader following the README "Recent audits" trail
hits a 404. The link rot was created by the same wave (v15) that
claimed to fix link rot — exactly the kind of regression the v15
gates were supposed to prevent.

**Fix (P0.1):** write a real `docs/audits/build-2026-05-29-v13.md`
reconstructed from the commit messages of `0804d7c`, `1295db5`,
and `30cbee1`. Mark it explicitly as **reconstructed post-hoc in
v16** so readers understand the provenance.

### P0.2 — `verify-ssot-integrity.sh` crashes confusingly against the local Path B mirror

Rule 09 was promoted to "normative-with-named-implementation" in
v15 P0. The named implementation,
[`scripts/verify-ssot-integrity.sh`](../../scripts/verify-ssot-integrity.sh),
returns the correct non-zero exit code (8 invariants fail on the
local mirror because Path B is a strict subset). But the failure
mode is **noisy and unhelpful**:

```
ERROR:  function digest(bytea, unknown) does not exist
ERROR:  column "word_count" does not exist
ERROR:  column "byte_size" does not exist
ERROR:  column "sha256" does not exist
ERROR:  column a.chapter_slug does not exist
ERROR:  column "format" does not exist
  ✗ chapters.sha256 drift:  rows
  ✗ chapters.word_count drift:  rows
  ...
❌ 8 invariant(s) FAILED
```

A user following the v15 bootstrap "Schema subset note" already
knows the local mirror is a subset, but the script does not detect
that and reports the missing-column ERRORs as if they were data
drift. This is exactly the "fail silently against the local mirror"
behaviour the v15 P2 note warned about — but the script itself
was not updated to detect it.

**Fix (P0.2):** add a preflight stanza to
`scripts/verify-ssot-integrity.sh` that detects the schema-subset
case (`SELECT column_name FROM information_schema.columns WHERE
table_schema='ssot_brochure' AND table_name='chapters' AND
column_name='sha256'` → 0 rows) and exits with code **99** plus a
clear message: "Detected Path B (local mirror) — schema-subset
mode is not supported; rerun against Path A (Pipedream) or Path C
(Railway DSN)." The script's docstring already lists exit-99 for
environment misconfiguration — extend the same exit code to schema
detection so the contract is uniform.

### P0.3 — Skill mirror references use upstream-repo-relative paths that don't resolve in skill context

v15 P0 / P1 / P2 added links of the form
`[scripts/qa_duplicate_prose.py](../../scripts/qa_duplicate_prose.py)`
to upstream rule files and then mirrored those files into the
skill `references/` directory. From inside the skill, `../../` ←
relative to `references/<file>` ← lands at
`/home/user/workspace/skills/user/`, which does **not** contain
the `scripts/` directory. Hard count of broken links per file:

```
05-brochure-qa-checklist.md  → 2
09-audit-and-rag-coverage.md → 1
03-safety-railway-postgres.md→ 2
agent-bootstrap.md           → 3
qa-brochure-pdf-checklist.md → 2
                              ──
                              10 broken
```

This is the same "skill mirror is not a 1:1 clone of upstream"
class of drift the entire skill exists to prevent.

**Fix (P0.3):** rewrite all 10 broken links in the skill copies
to use **absolute GitHub URLs**
(`https://github.com/gHashTag/trios-mcp-rag/blob/main/scripts/qa_duplicate_prose.py`).
Upstream `docs/agent-rules/*.md` keeps repo-relative links (they
work from the repo); skill copies get absolute URLs (they work
from anywhere). Document this divergence rule explicitly in rule
10 (next-wave workflow) so the mirroring step in future waves
applies the rewrite.

## P2 — operational hygiene

### P2.1 — `pre-commit` and `gitleaks` binaries not installed in the agent sandbox

Rule 03's v15 "Reference implementation" subsection names
`pre-commit-hooks v4.6.0` and `gitleaks v8.21.0`, but neither
binary is present in `$PATH` on the sandbox running this audit:

```
$ which pre-commit gitleaks
(no output)
```

The hooks fire only on a developer's local clone where
`pre-commit install` has been run; the agent sandbox has no such
setup and would happily commit a secret if asked to.

**Fix (P2.1):** add a "Bootstrap install" subsection to rule 03
giving the one-liner an agent should run on a new sandbox before
its first commit: `pip install pre-commit && pre-commit install`
(gitleaks is downloaded by pre-commit on first run). Reference
the official versions from the `.pre-commit-config.yaml`.

### P2.2 — skill's `scripts-inventory.md` does not list the missing-from-sandbox state

The v15-introduced `references/scripts-inventory.md` describes
six artefacts (5 scripts + the pre-commit / gitleaks pair) but
does not mention that the pre-commit hooks **must be installed
separately** on every new clone. An agent reading the inventory
would assume the hooks are always live.

**Fix (P2.2):** extend the
`.pre-commit-config.yaml` + `.gitleaks.toml` row in the inventory
to say "**Requires** `pre-commit install` after `git clone`. Hooks
do NOT run on an unconfigured clone."
