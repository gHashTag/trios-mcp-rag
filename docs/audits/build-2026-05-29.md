## Source data hygiene fixes applied during this build

The TSV snapshot needed three sanitisations before pandoc/tectonic
would accept it. These should be enforced as SSOT-level CHECK
constraints or sanitised in `tri ssot put`:

1. **Control characters** — strip `\x00-\x08`, `\x0b`, `\x0c`,
   `\x0e-\x1f` from `body_md` and `title`. Postgres rejects raw NUL
   bytes on insert; pandoc rejects the rest as "control characters
   are not allowed".
2. **Misclassified `illustration_url`** — 62/62 rows in this snapshot
   had `illustration_url` pointing at `.md` / `.pdf` / `.tex` files
   instead of images. Add a CHECK constraint
   `illustration_url IS NULL OR illustration_url ~* '\\.(png|jpe?g|svg|webp)$'`.
3. **Double-wrapped AMS math** — bodies contained
   `$$\begin{equation}…\end{equation}$$` and the same pattern for
   `align` / `gather` / `multline`. Pandoc wraps the outer `$$` as
   `\[ \]`, producing `\[\begin{equation}…\end{equation}\]` which
   amsmath rejects (`Erroneous nesting of equation structures`).
   Strip `$$` around any `\begin{<env>}…\end{<env>}` for the AMS env
   set in the SSOT linter.
