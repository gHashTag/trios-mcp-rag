# TRIOS PhD Canon (for RAG and agent retrieval)

This document is a stable, retrieval-friendly statement of the canonical
TRIOS PhD brochure invariants. It is intended to be indexed by RAG /
agent pipelines and re-read by any agent that touches the brochure
build. The rules in `docs/agent-rules/` remain normative; this file
collects the invariants that are most often forgotten between sessions.

## 1. Pipeline (recap)

Rust `trios-phd` / TRIOS MCP → Railway/Postgres SSOT
(`ssot_brochure.chapters` or `ssot.chapters`) → Markdown → `pandoc`
(`chapter.template.tex`, `force-fullwidth-hero.lua`) → LaTeX →
`tectonic` → PDF. No ReportLab / WeasyPrint / wkhtmltopdf substitutes.

See `docs/agent-rules/00-canonical-pipeline.md` for the full rule.

## 2. `TRIOS_PHD_NO_IMAGE_TRAIN`

`TRIOS_PHD_NO_IMAGE_TRAIN` is the named invariant covering hero / context
image placement in the brochure PDF.

### What it means

- Hero / context images **are required** on chapter openers and where a
  substantive section calls for one. The brochure is a *visual* PhD
  artefact — small, thumbnailed, or omitted heroes are a regression.
- Hero / context images **must be semantically anchored** to a nearby
  substantive heading and body text. The hero belongs to a section;
  the section is not a frame around a gallery.
- Heroes must **not** be rendered as a consecutive "image train" or
  "hero gallery" — that is, multiple hero-dominant pages back-to-back
  with no substantive prose between them.
- A short caption alone is **not** a text buffer. The buffer must be
  real paragraphs of substantive content.
- When the autogenerated source produces a duplicate or "transition"
  heading whose only content is a hero block (e.g. a section header
  that immediately repeats the next chapter's hero), keep the hero on
  the substantive section and **remove the transition hero**. The
  chapter opener's hero stays; the redundant gallery hero goes.

### How to enforce it (soft keep-together, not hard `\clearpage`)

The correct enforcement is a **soft keep-together** rule that groups
*section heading + hero/context block + first paragraph(s)* and asks
LaTeX to keep them on the same page when reasonably possible. In
practice this means:

- Use a samepage / needspace-style mechanism around the heading + hero
  + opening paragraph block.
- Allow LaTeX to break to the next page **only** when the block does
  not fit, not as a routine separator.
- Do **not** insert a hard `\clearpage` (or `\newpage`) before every
  section heading. Doing so creates short title-only pages whenever a
  section starts near the bottom of a page — a visible regression that
  inflates page count and produces low-context candidate pages that the
  QA scan will (correctly) flag.
- Hero placement may be `[H]` (here, definite) for chapter openers
  where the template guarantees it, with the float discipline coming
  from the keep-together group rather than from forcing a new page.

### Failure modes this rule prevents

- **Image train**: 2+ adjacent hero-dominant pages with <40 words of
  prose each. Symptom of a duplicate "transition" heading carrying a
  hero of its own. Fix at source: drop the transition hero.
- **Title-only short pages**: caused by a hard `\clearpage` per
  section when the previous section ended high on the page. Fix: use
  the soft keep-together rule, not a clearpage.
- **Orphaned hero**: a hero printed on a page whose body is empty or
  near-empty because the heading + hero were pushed by a hard break.
  Fix: same as above — soft keep-together, not hard break.

See `docs/qa/brochure-pdf-checklist.md` for the operational checklist

## 3. Accepted current QA baseline

The baseline below is the **accepted** state for the brochure PDF as of
the **post-v12 refinement pass (2026-05-29)**. Future builds should
meet or improve on each line; regressions need an explicit reason. The
authoritative numeric baseline lives in
`docs/qa/brochure-pdf-checklist.md` (operational checklist); the table
here is a mirror for RAG retrieval and is updated each wave.

| Metric                                        | Accepted value                  |
| --------------------------------------------- | ------------------------------- |
| Chapter count (`ssot_brochure.chapters`)      | **69** (post-v12)               |
| Page count (A4)                               | **259** (band: 240 ± 25)        |
| File size                                     | **3.5 MB** (~3 530 837 B)       |
| Reference sha256                              | `6d2e29ed32cc92b4aea32a0c639f7f16c646d94e1aa4adba97787869ec79293d` |
| `qpdf --check`                                | **clean** (exit 0)              |
| Exact duplicate long paragraphs               | **0**                           |
| Duplicate numbered headings                   | **0**                           |
| Cyrillic hits (public English build)          | **0**                           |
| Secret / stale / math anomaly hits            | **0**                           |
| Very short non-empty pages                    | **0** — **decisive regression signal** |
| Image-heavy / low-context candidate pages     | **1** (title page only)         |

**Baseline history:**

| Wave | Date       | Chapters | Pages | File size |
|------|------------|----------|-------|-----------|
| v8   | 2026-05    | 30+      | ~150  | n/a       |
| v10  | 2026-05    | 62       | ~242  | n/a       |
| v12  | 2026-05-29 | **69**   | **259** | **3.5 MB** |

Notes:

- "Image-heavy / low-context candidate" is the metric from rule 05 §4
  (Hero-anchoring scan): pages whose extracted text is below a
  small-prose threshold (≈40 words). The title page is expected to be
  image-heavy by design; it is the one accepted candidate.
- "Math anomaly" means LaTeX rendering of formulas leaking into the
  text layer in a way that suggests a broken `$…$` / `\(…\)` group
  (e.g. orphaned `\frac`, unmatched delimiters). The baseline is zero.
- "Very short non-empty page" is a page with non-empty extracted text
  but well below the prose threshold and not the title page. The
  baseline is zero — symptoms of a hard `\clearpage` per section would
  show up here.

**The decisive regression signal is row "very short non-empty pages"
(must stay 0), not absolute page count.** Page count tracks SSOT row
count and average chapter length, which naturally drift wave-to-wave.
A build that lands inside the 240 ± 25 band with row "very short
non-empty pages" still at 0 is accepted. A build outside the band
*without* short-page rise just means the SSOT changed size; verify
row count via `SELECT count(*) FROM ssot_brochure.chapters`. A rise
in short-page count — even with page count inside the band — is the
`TRIOS_PHD_NO_IMAGE_TRAIN` regression signature; read rule 02 and
`docs/qa/brochure-pdf-checklist.md` §2/§8 before publishing.
