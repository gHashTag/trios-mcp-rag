## P1 — structural items missing from the rule set

### P1.2 — New "Known non-paths" section in rule 03

Added a section to `docs/agent-rules/03-safety-railway-postgres.md`
(commit `1295db5`) documenting two approaches that look plausible
but **do not work**:

  - The Perplexity Computer **custom-credentials HTTPS proxy** can
    forward HTTPS but cannot route `libpq` wire-protocol traffic —
    saving a Postgres DSN as a custom credential does not give a
    working SSOT connection.
  - **No browser-side tool** (browser_task, fetch_url, vertical
    search) speaks `libpq`. Browsing the Railway dashboard is
    rendered-HTML viewing, not an SSOT read path.

The three correct paths (Pipedream connector, local TSV mirror,
local `.env` DSN) were cross-referenced to
`docs/agents/agent-bootstrap.md`.

### P1.3 — `AGENTS.md` Reference Index updated for rule 10

The reference index in `AGENTS.md` was extended with the rule 10
entry (commit `1295db5`).

## Why this document is reconstructed in v16, not v13

The v13 wave executed P0 / P1 / P2 fixes by editing rule files
directly and trusting the commit messages to carry the audit
narrative. v14 and v15 referenced "the v13 audit" as if a document
existed, and v15 P0 added explicit Markdown links from `README.md`,
`CLAUDE.md`, and `AGENTS.md` to `docs/audits/build-2026-05-29-v13.md`.
Those links 404-ed until v16 wrote this file. The lesson is encoded
as a new gate in rule 10: every wave that claims to fix link rot
MUST first verify that every link it adds resolves to an existing
file or external URL.
