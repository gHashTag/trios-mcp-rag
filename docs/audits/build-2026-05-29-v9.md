## Encoding lessons (v8 + v9)

1. **Pandoc `--from=markdown` default does NOT recognize `\(...\)` reliably** when surrounded by ambiguous markup. Switch to `$...$` form for ALL inline math we synthesise.
2. **Negative lookbehind on `$` is mandatory** when wrapping ASCII math to avoid double-wrapping. Inside `$...$` or `\begin{equation}...\end{equation}` blocks, ASCII tokens like `C^*` are already valid TeX — never re-wrap.
3. **8-space indent triggers pandoc `\begin{verbatim}`** which suppresses math rendering. Three theorem blocks in `p3-04-pellis-expansion` and `p3-05-projection` were indented at 8 spaces; dedented to 2 to enable inline math rendering of `$\infty$` and `$\mu_T$`.
4. **pdftotext layout extraction is unreliable**: it may show `S3AI` even when the PDF visually renders `S³AI` (TOC `\addcontentsline` flattens superscripts). Visual QA via `pdftoppm` is authoritative.
