## 1. Суть теории Trinity S³AI

Trinity S³AI — это физическая/математическая теория, утверждающая, что стандартные параметры Стандартной модели частиц (CP-нарушение δ_CP, масса Хиггса m_H, углы смешивания нейтрино и др.) **выводимы из первых принципов** через симметрийную группу H4 Coxeter без свободных параметров.

Ключевая предсказанная формула:

$$\delta_{CP} = \frac{3}{\varphi^2} \approx 65.66°$$

где φ — золотое сечение. Также утверждается тождество: φ² + 1/φ² = 3.

### Доктрина эпистемической примычности расчётов (EPISTEMOLOGY.md)

Центральный тезис ([EPISTEMOLOGY.md](https://github.com/gHashTag/trinity-s3ai/blob/main/EPISTEMOLOGY.md)):

> **Расчёты эпистемически первичны по отношению к измерениям**, когда расчёт получен из первых принципов без свободных параметров, а "измерение" — это модельно-зависимое извлечение через цепочку коррекций.

## 2. Сильные стороны теории

| Аспект | Описание |
|---|---|
| **Zero-parameter predictions** | Предсказания без свободных параметров — m_H, α₁/α₂/α₃, λ, PMNS θ₁₂/θ₁₃ проверены с <1σ |
| **Формальная верификация** | 1325-Qed корпус Coq-доказательств — машинно-верифицируемые теоремы |
| **Исторические прецеденты** | Три мощных кейса где «измерение» оказалось неверным: muon g-2 (2025), CDF W-boson (2024), нейтронное время жизни |
| **Строгая фальсифицируемость** | Чёткие критерии: что именно, при каком σ, в каком эксперименте убьёт теорию |
| **Pre-registration** | Все предсказания зафиксированы до получения данных в PREDICTIONS_PREREGISTERED.md |
| **Байесовская корректность** | Острый prior (одно число) vs жирный likelihood (модельно-зависимое извлечение) — корректный байесовский аргумент |
| **Честность** | Отдельные файлы HONEST_ASSESSMENT, HONESTY_MANIFEST — открытое признание нерешённых проблем |

## 3. Слабые стороны теории

| Аспект | Описание |
|---|---|
| **δ_CP в 5.6σ натяжении** | Предсказание 65.66° vs извлечённые ~195° — серьёзная напряжённость даже с оговоркой о модельной зависимости |
| **T2K+NOvA взаимное 2σ противоречие** | Даже принимая аргумент о модельной зависимости, два независимых эксперимента противоречат предсказанию |
| **Риск unfalsifiability через эскапизм** | Доктрина «все измерения модельно-зависимы» при неосторожном применении превращается в нефальсифицируемость |

| **Ожидание DUNE 2028** | До модельно-чистых измерений δ_CP теория находится в подвешенном состоянии |

## 4. Пайплайн: Railway/Postgres SSOT → Markdown → pandoc → LaTeX → tectonic → PDF

Эта архитектура превращает Railway Postgres как единый источник истины (SSOT) в готовые научные PDF через цепочку трансформаций.

### 4.1 Сильные стороны пайплайна

- **Single Source of Truth**: все данные хранятся в Postgres на Railway — нет рассинхронизации между разными форматами
- **Версионируемость**: каждое изменение в БД → новый Markdown → новый PDF, полный аудит через git
- **Автоматизация**: полный CI/CD от данных до публикации без ручного вмешательства
- **LaTeX качество**: через pandoc + tectonic получаем типографски безупречный PDF (в отличие от HTML-to-PDF)
- **tectonic vs pdflatex**: tectonic автоматически скачивает нужные пакеты, нет проблем с зависимостями TeX
- **Научная воспроизводимость**: PDF — это снимок состояния БД в конкретный момент времени
- **Pandoc гибкость**: один Markdown → PDF, HTML, EPUB, docx одновременно

### 4.2 Слабые стороны пайплайна

- **Сложность отладки**: ошибка в LaTeX-шаблоне pandoc ломает весь пайплайн, найти источник трудно
- **Математические формулы**: перевод из Postgres TEXT → Markdown → LaTeX требует аккуратного экранирования $ и \\
- **Латентность**: для real-time документов задержка Railway query → PDF неприемлема
- **Размер образа**: tectonic + TeX Live = ~500MB Docker образ
- **Pandoc Markdown ≠ CommonMark**: некоторые расширения pandoc не поддерживаются в GitHub
- **Lock-in на Railway**: при миграции на другой хостинг нужно переносить connection strings и env vars
- **Отсутствие diff для PDF**: Git не умеет делать meaningful diff PDF-файлов, только binary

## 5. Архитектура MCP-интеграции (trios-mcp-rag)

Для интеграции пайплайна в [trios-mcp-rag](https://github.com/gHashTag/trios-mcp-rag) предлагается следующая схема MCP-инструментов:

```
Railway Postgres
    │
    ▼ (SQL query)
Markdown generation (Rust/trios-mcp-rag)
    │
    ▼ (pandoc --from markdown --to latex)
LaTeX source
    │
    ▼ (tectonic)
PDF output
    │
    ▼ (S3 / Railway Volume upload)
Public PDF URL
```

### MCP Tools для добавления в trios-mcp-rag

1. `generate_markdown_from_db` — запрос к Postgres, генерация Markdown
2. `render_pdf_from_markdown` — pandoc + tectonic, возврат PDF blob или URL
3. `upload_to_storage` — загрузка в Railway Volume или S3
4. `get_theory_snapshot` — получение текущего состояния теории как structured JSON из SSOT
