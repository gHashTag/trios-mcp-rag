## P1 — formal precision (regex + exclusion lists)

### P1.1 — rule 07 §2 "falsification-path gate" has no formal marker regex

The eight chapters that mention "open conjecture" use five different
syntaxes:

```
fm-01c-prologue          latex-emph     (\emph{Open conjecture})
fm-01d-reading-paths     latex-emph
fm-01e-at-a-glance       latex-emph
fm-13-depin-positioning  backtick-caps  (`OPEN CONJECTURE`)
p1-10-falsification      md-bold        (**Open conjecture**)
p1-14-conclusion         plain          (no markup)
p2-14-conclusion         md-bold
p3-13-phd-integration    latex-cmd      (\statusOpen)
```

Three of these are **taxonomy-definition contexts** (the three
`fm-01[cde]` prologue chapters), one is the **falsification ledger
chapter itself** (`p1-10-falsification`), and the rest are real
claim sites that should carry a `falsification_path`. A naive
`ILIKE '%open conjecture%'` falsely flags the taxonomy definitions
and the ledger chapter.

**Fix (P1.1):** in rule 07 §2, add an explicit "marker regex"
specification that lists the four accepted concrete markers
(`\*\*Open conjecture\*\*`, `\\emph\{Open conjecture\}`,
`` `OPEN CONJECTURE` ``, `\\statusOpen`) and an explicit slug-prefix
exclusion list (`fm-01c-*`, `fm-01d-*`, `fm-01e-*`, `p1-10-*`) so a
linter can be written against the spec without false positives.

### P1.2 — rule 04 hype-scan does not distinguish hype from external-validation references

Rule 04 forbids "Nobel claims as deliverables — only as long-term
external-validation standards". A naive grep for `Nobel` therefore
fires on legitimate references (e.g. Shechtman quasicrystals Nobel
in `p3-10-worked-examples` and the discussion of Nobel-level
validation in `fm-07-olsen-tier-d`). These are exactly the
"external-validation standard" usage rule 04 permits.

**Fix (P1.2):** in `references/qa-brochure-pdf-checklist.md` (and
mirror in the skill copy), add a "Hype-scan context exclusions"
subsection that lists allowed patterns:

  - historical award references about external work
    (`Nobel Prize ... (won|awarded|received)`)
  - direct citation of an external Nobel laureate by name with
    DOI / external link in the same paragraph

and require any new match to be triaged before being treated as a
violation.

### P2.2 — local-mirror schema is a strict subset of Railway but the difference is not stated up-front

The v13 audit established that the Railway `ssot_brochure.chapters`
table carries extra columns (`sha256`, `word_count`, `byte_size`,
`format`, `asset_sha`, `updated_at`) that the local TSV mirror does
not have. Rule 03 and `references/agent-bootstrap.md` describe the
three SSOT access paths but do not explicitly say "the local mirror
schema is a **strict subset**" — an agent could plausibly write code
against the Railway columns and have it silently fail against the
local mirror.

**Fix (P2.2):** add a "Schema subset note" to `references/agent-bootstrap.md`
explicitly stating that the local mirror schema is a strict subset
and that any code that depends on the extra columns must declare
which access path it requires.
